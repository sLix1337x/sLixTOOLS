# sLixTOOLS — Improvement Report

Generated 2026-07-17. Analysis of the full codebase: build config, CI, source, service worker, SEO, dependencies.

---

## 1. Critical — likely broken in production

### 1.1 FFmpeg video tools probably fail on GitHub Pages
- `vite.config.ts` sets COOP/COEP headers in the **dev server only**. GitHub Pages cannot send custom headers, so `SharedArrayBuffer` is unavailable in production.
- `src/utils/videoProcessor.ts:431` and `:753` throw if `SharedArrayBuffer` is undefined → Video-to-GIF and Video Converter likely error out for all production users.
- Fix options: (a) use single-threaded `@ffmpeg/core` (doesn't need SharedArrayBuffer) and remove the check, or (b) add [coi-serviceworker](https://github.com/gzuidhof/coi-serviceworker) to enable cross-origin isolation on GH Pages.

### 1.2 Service worker is dead code — but README claims "PWA Ready"
- `public/sw.js` (414 lines) is **never registered** — no `navigator.serviceWorker.register` anywhere in `src/` or `index.html`.
- Its contents are also wrong for this app:
  - `STATIC_ASSETS` references `/favicon.ico`, `/logo192.png`, `/logo512.png` — none exist.
  - Caches `/api/audio/info`, `/api/video/info` — this app has no API.
  - `DYNAMIC_ROUTES` like `/video-to-gif` don't match actual hash-based routes (`/#/tools/video-to-gif`).
  - All paths ignore the `/sLixTOOLS/` base path.
- Fix: delete it, or replace with `vite-plugin-pwa` (Workbox) which generates a correct precache manifest automatically.

### 1.3 Type errors: `tsc --noEmit` fails with 59 errors
- Real bugs: `VideoToGif.tsx:242` and `:327` pass objects (`EditParams`, `ConversionOptions`) where primitives are expected.
- `src/hooks/index.ts` exports `UseToolFileOptions`/`UseToolFileReturn` **twice** (duplicate identifier).
- Rest is unused imports/variables (`React`, `Loader2`, `Button`, dead vars in `PdfEditor.tsx`, unused ffmpeg imports in `videoProcessor.ts`).

### 1.4 Broken social preview image
- `index.html` og:image / twitter:image point to `assets/images/slixtool-banner.svg` — the file doesn't exist (`public/images/` contains only `funkykong.gif`, `kofi.png`, `vorncrash2.gif`). Link previews on social media are broken.

### 1.5 manifest.json ignores base path
- `start_url: "/"` and icon `src: "/formen.png"` resolve to the domain root, not `/sLixTOOLS/`. PWA install would use wrong URLs. Also both icon entries point to the same file while claiming 192px and 512px sizes; `pwa-192x192.png` exists but is unreferenced.

## 2. CI / Build

### 2.1 No quality gates before deploy
- `.github/workflows/deploy.yml` runs only `npm run build`. Neither `tsc --noEmit` nor `eslint` (currently 12 errors, 43 warnings) is run. Broken code deploys silently. Add a check job that gates deploy.

### 2.2 `npm ci --legacy-peer-deps`
- Masks peer-dependency conflicts (likely Vite 7 vs. plugin versions). Resolve the conflicts and drop the flag.

### 2.3 Redundant SPA fallback
- CI copies `dist/index.html` → `404.html` AND `public/404.html` exists AND the app uses `HashRouter`. With hash routing, 404 fallback is unnecessary; pick one strategy (see 5.1).

### 2.4 Committed build artifacts of dependencies
- `public/workers/` (gif.worker.js, pdf.worker.min.mjs) is committed but also regenerated by `copyWorkerFiles()` on every build. Add to `.gitignore` — versions silently drift from `node_modules` otherwise.

### 2.5 Debug step in CI
- "Debug Environment" step (`npm list --depth=0` etc.) adds noise/time; remove or make conditional.

## 4. Architecture / Code quality

### 4.1 PdfEditor.tsx is a 1,665-line god component
- ~20 `useState` hooks plus all editor logic in one file, while 20 smaller `components/tools/pdf/*` already exist.
- Extract state into `useReducer` or custom hooks (`usePdfDocument`, `usePdfAnnotations`, `usePdfSelection`).
- `PDF_EDITOR_REDESIGN_PLAN.md` already describes this — it was never executed.

### 4.2 Tool pages don't use the shared hooks
- `useToolFile` / `useProcessingState` exist, but only 2 of 9 tool pages use them. `ImageCompressor`, `ImageResizer`, `ImageConverter`, `GifCompressor` (300–400 lines each) re-implement the same upload → options → process → download flow with 5–10 local `useState` each. Consolidating into the shared hooks + `ToolPageLayout` would cut hundreds of duplicated lines.

### 4.3 `videoProcessor.ts` (980 lines) has two near-identical code paths
- Two full ffmpeg load/exec/cleanup implementations (~lines 427–740 and 749–890) duplicating base-path resolution, error classification, and SharedArrayBuffer checks. Extract one `loadFFmpeg()` + `runFFmpeg()` helper.

### 4.4 ErrorBoundary.tsx is 598 lines
- An error boundary should be ~50–100 lines. Move retry/logging/reporting logic into `utils/` or split into `AppErrorBoundary` / `ToolErrorBoundary`.

### 4.5 App.tsx route boilerplate
- 15 routes each hand-wrapped in `<Suspense>` with custom text. Map over a route config array with one shared Suspense wrapper.

### 4.6 vite.config.ts doing too much (~200 lines)
- Worker copying + dev middleware + MIME fixes inline. Extract the copy-workers plugin to `scripts/` or replace with `vite-plugin-static-copy`.

## 5. Routing / SEO

### 5.1 HashRouter hurts SEO
- All URLs are `/#/tools/...`. Crawlers treat hash routes poorly; `SEO.tsx`/helmet canonical tags are largely wasted. GH Pages supports the `404.html` redirect trick with `BrowserRouter` — infra for it already half-exists (see 2.3). Consider switching.

### 5.2 Missing structured data & sitemap
- No `sitemap.xml`; `robots.txt` exists but can't help crawlers discover hash routes. No JSON-LD (`WebApplication`/`SoftwareApplication` schema would fit these tool pages well).

### 5.3 `index.html` meta
- No `theme-color` meta tag (manifest has `#2AD587`). Favicon is `formen.png` via relative path — fine, but no SVG/ICO fallbacks.

## 6. Security

### 6.1 CSP weakened by `unsafe-inline` + `unsafe-eval`
- `script-src 'self' 'unsafe-inline' 'unsafe-eval' blob:` — `unsafe-eval` is likely needed for WASM (prefer `'wasm-unsafe-eval'`), but `unsafe-inline` for scripts should be removable with Vite. `img-src ... https:` allows loading images from any HTTPS origin — tighten if possible.

### 6.2 npm audit: 8 vulnerabilities (5 high, 3 moderate)
- Includes `yaml` stack-overflow advisory. Run `npm audit fix`, review the rest. Add Dependabot/Renovate (`.github/dependabot.yml`) so this doesn't recur.

## 9. Accessibility

- Only 3 component files use any `aria-*` attribute.
- File upload areas, the PDF toolbar/ribbon (80+ buttons), and custom controls need labels (`aria-label`), keyboard focus states, and drag-drop announcements.
- Heavy animation (framer-motion, particles, smooth scroll) with no `prefers-reduced-motion` handling found — worth auditing.
- Suggest one pass with axe DevTools / Lighthouse a11y.
